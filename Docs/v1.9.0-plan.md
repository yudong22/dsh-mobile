### 实施中发现的、规划未预见的问题

实现时暴露了两处只有当抽屉「活得比页面久」才会出现的缺陷——原规划把抽屉
提升视为纯结构调整，实际不是：

1. **抽屉会留在目标页面上方**：提升前它随 `WorkspaceScreen` 销毁，提升后不销毁，
   于是在抽屉里点「插件」/「新建任务」后它仍半开着盖住新页面。
   修法：所有外向动作（切任务、切项目、新建、插件）都先 `settle(open = false)`。
2. **会话页切任务会重复压栈**：抽屉现在能在会话页打开，而该路径原先是裸 `navigate`，
   连点 N 个任务会压入 N 层。修法：`requiresConversationNavigation()` ——
   已在会话页时只切选中、不导航。

两者都由设备测试抓出（`AndroidUiParityDeviceTest`、新增 `ConversationDrawerButtonDeviceTest`），
单测与编译都发现不了。

### 顺带修掉的既有 flake

`ConversationKeyboardDeviceTest` 的 IME 位移用例是**既有**间歇失败（不是本版引入）：
在未改动的 `de24f9b` worktree 上实测同样 5 次里失败 1 次。探针定位到真因——
它断言的是 `LazyColumn` 里的消息气泡，而该节点会被回收，约 1/4 的运行里
聚焦后整整 5 秒都不在语义树中（`bubbleSeen=0`）。改为锚定**输入框**
（始终被组合，且正是 `imePadding()` 作用的节点）后 12/12 全绿；
并用变异测试确认断言强度未削弱（移除 `imePadding()` 仍会失败）。

## 1. 点 1（体验 bug）：切后台回来弹「好 / 重新连接」

### 1.1 现象与两个独立缺陷

**缺陷 A：两个按钮视觉完全相同。**
`DshAlertDialog.kt:96-118` 的 `DshAlertDialogButton` 对两个按钮使用**同一套**样式
（`onSurface.copy(alpha = 0.08f)` 底 + `weight(1f)`），没有任何主次变体。
所以 `DshProductApp.kt:189-202` 传的 `dismissLabel = "好"` 与 `confirmLabel = "重新连接"`
在屏幕上就是两个一模一样的灰胶囊——用户说「看起来没有区别」是字面事实，不是错觉。

**缺陷 B：传输类失败被无条件升级成模态错误。**
`AndroidSharedStateHolder.kt:666`（`GatewayRuntimeEvent.RequestRejected` 分支内）：

```kotlin
platformError = "${event.requestType}: ${event.reason}"
```

这是**无条件**赋值。而 `GatewayRuntime.kt:347-356` 规定：只要 `connection != CONNECTED`，
**任何** `sendRequestLocked` 都会被拒：

```kotlin
if (mutableState.value.connection != GatewayConnectionState.CONNECTED) {
    rejectLocked(request.requestType, ERROR_NOT_CONNECTED, ...)   // "not-connected"
    return false
}
```

于是「切后台 → 前台」这条正常路径必然报错：

1. 后台：`DshAndroidApplication.kt:50-56` → `applicationDidEnterBackground()`
   → `GatewayRuntime.kt:241-251` 主动 `cancelPendingLocked(ERROR_BACKGROUND_SUSPENDED)` +
   `transport.close()`，连接置 `SUSPENDED`；
2. 前台：`DshAndroidApplication.kt:44-48` → `applicationDidBecomeActive()`
   → `GatewayRuntime.kt:253-262` `scheduleReconnectLocked(immediate = true)`；
3. **但在重连完成之前**，Compose 的 `LaunchedEffect(connection)` 已经触发了刷新请求：
   `DshProductApp.kt:273`（`refreshProductState`）、`ScheduledTasksScreen.kt:95-99`、
   `ConversationScreen.kt:204-206`、以及重连回调 `AndroidSharedStateHolder.kt:339-343`
   （`catchUpSelectedHistoryAfterReconnect` / 重新订阅）；
4. 这些请求撞上 `CONNECTED` 未成立 → `rejectLocked(..., "not-connected")`
   → `AndroidSharedStateHolder.kt:666` → **弹窗**。

**已存在的证据**：`AndroidUiParityDeviceTest.kt:82` 断言
`hasText("unsubscribe: not-connected")` **不得出现**——说明这个内部 token 泄漏成用户文案
是**已知的既有缺陷**，只是从未堵住源头。

### 1.2 静默重连其实早就有了

`GatewayRuntime.kt:1059-1079` 的 `scheduleReconnectLocked` 带指数退避：

```kotlin
val next = (mutableState.value.reconnectAttempt + 1).coerceAtMost(6)
clock.delay((2_000L shl (attempt - 1)).coerceAtMost(30_000L))   // 2s→30s
```

调用点：`:521`（可恢复传输失败）、`:857`（网络恢复）、`:258`（回前台）、`:1037`（多地址超时）。
闸门 `canReconnectLocked()`（`:1016-1018`）。

**所以本版不需要新建重连机制**，只需要：把「重连期间的请求被拒」从模态错误里剔除，
并把弹窗的按钮语义做对。要修的是一处漏斗，而不是 48 个赋值点。

### 1.3 哪些必须静默、哪些必须保留

`platformError` 共 48 个赋错点。按来源分类：

**→ 静默（传输/生命周期类，用户无法也无需处理）**
- `:666` `RequestRejected` 漏斗中 reason ∈ 传输类集合
  （`not-connected` / `send-failed` / `request-busy` / `request-coalesced` /
  `gateway-request-failed` / `connection-replaced` / `connection-closed` /
  `connection-recycled` / `background-suspended` / `network-lost` / `recovery-timeout` /
  `stale-frame` / `no-active-request` / `request-timeout`）
- `:508` / `:577` / `:641`：仅 `queue-update` 的 `queueState.lastError`（同类 reason）
- `:1392`（agent preset 传输失败）、`:1986`（slash command 传输失败）、
  `:1504`（goal 超时）、`:74`（后续队列）、`:2228`（工作区文件快照）
- `:710` 冷启动 `stored-connect-failed`

**→ 保留（真实用户动作失败，必须可见）**
- 配对：`:1610-1624`（配对码/二维码解析失败）
- 手动连接：`:1590-1595`（`connect-failed`）
- 新建会话前置：`:927` / `:931`（「请先连接」/ 能力缺失）、`:955` / `:975`
- 目录/工作区：`:1042` / `:1050` / `:1058` / `:1063` / `:1075` / `:1087` / `:1096` /
  `:1109` / `:1113` / `:1117`
- 目标/命令/图片/停止/下载：`:1477` / `:1481` / `:1490`、`:1714`、`:1915`、`:2057`、
  `:2149` / `:2160` / `:2187` / `:2204`、`:1643-1664`
- 本地缓存读失败：`:807`

**硬约束：配对码绝不静默重试。** `GatewayRuntime.kt:131-132` 的注释与
`:513`（`isManualPairingAttempt → reconnectBlocked = true`）、`:1017`、
`:1040-1042` 共同保证这点。本版**不得**放宽这条，否则会重放已消费的一次性配对码。

### 1.4 修法

- **[ ] A. 收敛错误来源**：在 `AndroidSharedStateHolder.kt:666` 加传输类 reason 过滤，
  传输状态本身已由顶栏状态点承担（`DshBottomNavigation.kt:219-262`、
  `DshConnectionStateUi.kt:42-50`），静默不丢失信息；
- **[ ] B. 内部 token 不再直出**：`:710` / `:1594` / `:1659` / `:1664` 四处把英文 token
  直接当文案（用户会看到 `stored-connect-failed`）。参照既有 `slashCommandErrorMessage`（`:2062`）
  与 `workspaceFileErrorMessage`（`:2259`）的范式，加一个 `platformErrorMessage(code)` 映射；
- **[ ] C. 按钮语义分级**：`DshAlertDialogButton` 增加 `primary: Boolean` 变体
  （实心主色 vs 次级灰）——这是「两个按钮没区别」的直接修法；
- **[ ] D. 弹窗按钮按状态收敛**：仅当重连**确实被阻断**时才给「重新连接」；
  自愈态（CONNECTING / AUTHENTICATING / WAITING_FOR_NETWORK）只给单个「好」。
  `reconnectBlocked` 是 `private`（`GatewayRuntime.kt:130`），需要时把它作为字段暴露到
  `GatewayRuntimeState`，**不要**用连接状态反推；
- **[ ] E. 顺带修掉信息泄漏**：`:666` 的 `"${requestType}: ${reason}"` 格式把内部
  requestType 也暴露给用户（`history: gateway-request-failed`）。改为用户可读文案。

### 1.5 验收标准

- 切后台再回前台，**不出现任何弹窗**；连接状态点自行从「连接中」回到「已连接」；
- 真机断网 → 恢复网络，不弹窗，状态点自愈；
- 输入错误配对码 → **必须**弹窗且文案为「配对信息无效」等可读中文；
- 手动点「连接」到一个不可达地址 → **必须**有反馈；
- 单测：传输类 reason（含 `not-connected`）不设置 `platformError`；
  配对失败**必须**设置；
- 单测：`platformErrorMessage` 对四个已知 token 返回中文，对未知 token 有兜底。

> **必须同步更新的测试**：`AndroidAppGraphFakeIntegrationDeviceTest.kt:167`
> `waitUntil { holder.platformError?.startsWith("history:") == true }`
> 依赖 `"${requestType}: ${reason}"` 格式。1.4.E 改格式后这里必须同步改。
> 注意该用例要保留的是「history 失败仍能上报」这一**行为**，而不是那个前缀。

## 2. 点 3（体验）：项目页选项目后自动回任务列表

### 2.1 根因：选中已正确，导航完全缺失

`DshTabScreens.kt:51-54` 的签名只有 `onBack`，**没有任何「已选中」回调**，
所以这个页面**没有能力**导航：

```kotlin
internal fun ProjectsTabScreen(stateHolder: AndroidSharedStateHolder, onBack: () -> Unit)
```

两个点击处理都只调选中（`:88` 未分组 / `:96` 项目行）：

```kotlin
onClick = { stateHolder.selectWorkspace(workspace.workspaceId) }
```

选中链路本身是对的：`selectWorkspace`（`AndroidSharedStateHolder.kt:1024-1027`）
→ `applyWorkspaceSelection`（`:2266-2276`）**同步**改 `selectedWorkspaceId`
（Compose state，`:148`）并**异步持久化**（`preferences.update`）。
不依赖导航就会自动刷新的下游：`activeWorkspace`（`:1013-1019`）、
`isUngroupedWorkspaceSelected`（`:1021-1022`）、`workspaceScopedSessions`
（`DshProductApp.kt:283-289`，key 含 `selectedWorkspaceId`）、
项目卡（`:377` / `:495-540`）、`HomeRecentSessions`（`:392`）。

`ROUTE_PROJECTS` 恒由首页压栈（`:146`），所以 `popBackStack()` 就是回任务列表。

对比：抽屉（`WorkspaceDrawer.kt:317/327` → `DshProductApp.kt:350`）与运行时设置面板
（`DshRuntimeSettingsSheet.kt:243-245`）都只切换、不导航，且都在**用户预期留在原地**的容器里。
**项目页是唯一一个把用户留在子页面的入口。**

### 2.2 修法

- **[ ] A.** `ProjectsTabScreen` 增加 `onProjectSelected: () -> Unit`；
- **[ ] B.** `:88` 与 `:96` 在 `selectWorkspace(...)` 之后调用它；
- **[ ] C.** `DshProductApp.kt:182-187` 传 `navController::popBackStack`；
- **[ ] D.** **已选中的项目行也必须导航返回**。`applyWorkspaceSelection:2267` 对
  同值提前返回，若把导航也 gate 掉，这一行就成了死行——点击被吞掉；
- **[ ] E.** 不要在点击处补 `refreshProductState()`：`:65` 的 `LaunchedEffect(Unit)` 已有，
  且选中状态变化本身就驱动了所有下游投影。

### 2.3 验收标准

- 点「项目」Tab 任一项目行（含未分组）→ 回到任务列表，项目卡标题/路径随之更新，
  `home-recent-sessions` 只含该项目的会话；
- 点**已选中**的项目行同样返回（不是死行）；
- 设备测：新增「点项目行 → 断言 `workspace-card` 已切换 + 底栏回到 `tab-tasks` 选中态」。

## 4. 点 6 + 点 5（核心重构）：抽屉与底栏提升为应用外壳

这两点必须一起做。点 5 要会话页有抽屉，点 6 要核心页面有底栏；

### 4.3 会话页底栏与键盘的冲突（本版最大风险）

**事实**（已逐行核对）：

- `ConversationScreen.kt:215-263` 的 `Scaffold` **没有** `bottomBar`，也没设
  `contentWindowInsets`，走默认系统栏 inset；
- `:264-270` `Column(...).padding(padding).consumeWindowInsets(padding)`；
- 输入区 `:516-524` 用 `.imePadding()` + `.navigationBarsPadding()`，
  并用 `onSizeChanged` 把高度写进 `bottomContentHeight`，
  后者驱动时间线 `contentPadding.bottom`（`:923-926`）与底部渐隐（`:512-515`）；
- 时间线自己也 `.imePadding()`（`:916-922`）；
- `AndroidManifest.xml` 为 `adjustResize`，且被
  `AndroidUiParityDeviceTest.kt:28-34` **钉住**；`MainActivity.kt:21` `enableEdgeToEdge()`。

**风险**：Scaffold 把 `bottomBar` 摆在 `layoutHeight - barHeight`；
`adjustResize` 下键盘弹出会缩小 `layoutHeight`，于是一个**不感知 IME** 的 84dp 底栏
（`DshBottomNavigation.kt:81-88` 只处理 `navigationBarsPadding()`）
会被顶到**键盘正上方**，与同样上浮的输入框叠在一起，吃掉约 84dp 输入区。
首页从不暴露这个 bug，因为它没有输入框。

**修法（采用 (a)）**：

- **[ ]** 会话页的 `bottomBar` 以 `WindowInsets.isImeVisible` 为闸门
  （`ConversationScreen.kt:469` 已在读它）：键盘可见时**不渲染**底栏。
  这是最小且行为可预测的方案，且因为底栏消失，Scaffold 的 `padding.bottom` 归零，
  与 `bottomContentHeight` 的自适应逻辑自洽。
- 备选 (b)把底栏塞进输入框 Column 内——会与 `bottomContentHeight`、
  `ConversationBottomFade`、审批/提问面板打架，**不采用**。

### 4.4 抽屉提升后的手势冲突（未知项，必须真机验证）

## 5. 点 2（体验）：点底栏不要左滑动画

### 5.1 根因

`DshProductApp.kt:112-127` 在 `NavHost` 上设了**全局**过渡：

```kotlin
enterTransition = { slideIntoContainer(SlideDirection.Left, tween(260)) }
exitTransition = { slideOutOfContainer(SlideDirection.Left, tween(260)) }
```

10 个 `navigate` 调用中，只有 3 个是底栏切换（`:143` 设置 / `:145` 定时任务 / `:146` 项目，
经 `:410-412` 派发）；其余是真实下钻（会话、通知深链、插件、设置子页），
**下钻保留滑动是合理的**，不该一起砍掉。

**版本已核实**：navigation-compose **2.9.3**（`gradle/libs.versions.toml:6`）；
已用 `javap` 反编译缓存 AAR 确认
`composable(route, …, enterTransition, exitTransition, popEnterTransition, popExitTransition, …)`
存在，**支持按目的地覆盖过渡**。

### 5.2 修法

- **[ ]** 对 `ROUTE_PROJECTS`（`:182`）、`ROUTE_SCHEDULED_TASKS`（`:169`）、
  `ROUTE_SETTINGS`（`:152`）三个 Tab 目的地覆盖为 `EnterTransition.None` /
  `ExitTransition.None` / `popEnterTransition` / `popExitTransition` 全 None；
- **[ ]** `NavHost` 全局默认**保持滑动**，供下钻使用；
- **[ ]** 点 6 完成后复核：若会话页也挂底栏，需要决定「会话 ↔ 首页」是否算 Tab 切换。
  建议**不算**（会话是任务的详情，保留下钻语义）。

### 5.3 验收标准

- 点底栏四个目的地，页面**瞬时**切换，无横向滑动；
- 首页点会话行、设置点「Agent 预设」、通知深链**仍有**滑动；
- 设备测不需要为动画加 `waitForIdle`：现有 Tab 用例**零** `waitForIdle` / `mainClock`，
  去掉动画只会更稳定，不会破坏断言（已全量 grep 确认）。

## 6. 并入 v1.8.3 的 3 项遗留

用户确认「全部纳入本版一并发」。以下三项经复核**确实尚未实现**。

### 6.1 A：扫码后旧连接消失

`AndroidMultiGatewayStore.kt:294-311` `pairingProfile()`：

```kotlin
val existing = profiles.firstOrNull {
    if (payload.gatewayId != null) payload.gatewayId.equals(it.gatewayId, true)
    else it.gatewayId == null && endpoints.first() in it.endpoints   // ← 靠首个地址
}
return profile.copy(endpoints = endpoints, preferredEndpoint = endpoints.first())  // ← 覆盖
```

- **缺陷 A（地址丢失）**：`endpoints = endpoints` 是覆盖不是并集，
  远程地址被新扫码结果整体替换；
- **缺陷 B（身份漂移）**：`gatewayId == null` 时靠 `endpoints.first()` 匹配，
  二维码地址顺序不同即判定为「新设备」→ 新建 profile → 新 `localId`
  → 挂在该 `localId` 下的会话缓存（`host_$localId`）全部对不上。

修法：`existing` 命中时取**并集**（受既有 `MAX_ENDPOINTS = 16` 约束，
优先保留 `preferredEndpoint` 与最近连通的）；`gatewayId == null` 时改为
**整个 endpoint 集合求交**而非 `first()`，仍无法判定才新建；为已有重复 profile 补一次
**幂等迁移**（合并同 `gatewayId`/同 `gatewayName` 且地址有交集的条目，
保留更早的 `localId` 以免丢缓存）。

验收：同一网关扫两次（远程优先 / 本地优先）后 `profiles` 中**只有一条**、
`localId` 与首次一致、`endpoints` 同时含两个地址；切回旧设备立即可见缓存内容。

> 这是**客户端兜底**。根治要网关在二维码里始终带 `gatewayId`（协议侧）。

### 6.2 B：抽屉「空间」默认收起 + 改名「项目」

- `WorkspaceDrawer.kt:120` `var spacesExpanded by remember { mutableStateOf(true) }` → `false`；
- `:302` `label = "空间"` → `"项目"`；
- **测试影响已核实为零**：`drawer-section-空间` 没有任何断言（全量 grep 确认）。
  但注意 `:488` `testTag("drawer-section-$label")` 会随之变成 `drawer-section-项目`；
- 建议同时把展开态改 `rememberSaveable`（现在旋转会丢）；
- 一致性检查：`DshRuntimeSettingsSheet.kt:152/179/222/228` 仍用「工作空间」，
  与底栏/抽屉的「项目」并存。**这是既有术语分叉**，本版只统一抽屉与底栏，
  运行时设置面板是否一并改列为决策 D3。

### 6.3 C：工作区映射不持久化 → 离线分组错误

`GatewayPlatformContracts.kt:84-88`：

```kotlin
data class GatewayPreferencesSnapshot(
    val endpoint: String = ...,
    val selectedWorkspaceId: String? = null,
    val sessionsJson: String? = null        // ← 没有 workspaces
)
```

后果：冷启动/离线时 `availableWorkspaces` 为空 →
`workspaceScopedSessions`（`DshProductApp.kt:571-586`）把所有会话判为「未归属」
→ **分组错误**（不是空列表，更容易被当真）。

修法：新增 `workspacesJson`（编码方式同 `sessionsJson`），
在 `AndroidGatewayPreferences`（`:35-44`）读写；投影侧仿
`exportSessionCache` / `restoreSessionCache`（`AndroidGatewayProjection.kt:113` / `:146`）
增加导出/恢复；恢复**只填列表、不发网络 effect**；
复用「权威内容」守卫——收到过 `workspaces` 帧后不得再被缓存覆盖。

> **契约变更**：`GatewayPreferencesSnapshot` 是 shared KMP 类型。
> Android 侧实现 `AndroidGatewayPreferences.kt`；测试实现需同步
> （`AndroidGatewayRuntimeIntegrationTest.kt:197`、
> `AndroidAppGraphFakeIntegrationDeviceTest.kt:281`、`GatewayRuntimeIntegrationTest.kt:1470`）。
> iOS 侧有独立的 `AppPreferences.swift`（`selectedWorkspaceID`，`:17`），
> **不实现该共享接口**，故本项需确认 iOS 是否受影响（决策 D4）。

验收：断网冷启动，抽屉按**上次的项目**正确分组；联网后宿主数据覆盖缓存。
